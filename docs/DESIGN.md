## 1. 核心设计哲学与系统基石 (Core Philosophy & Foundations)

在 Apple 看来，夜间屏幕调光的核心命题不是“生硬压低数值”，而是**重构人眼与发光屏幕在暗光环境下的温和共生关系**。

```
       ┌────────────────────────────────────────────────────────┐
       │                Luna Dimmer 五大工程架构基石             │
       ├─────────────────────────┬──────────────────────────────┤
       │ 1. 物理真实感 (Optics)   │ 拒绝死色遮罩，重构光线物理吸收路径 │
       ├─────────────────────────┼──────────────────────────────┤
       │ 2. 连续性隐喻 (Fluidity)│ 超椭圆曲率、等宽字阶与流体弹性阻尼 │
       ├─────────────────────────┼──────────────────────────────┤
       │ 3. 系统的契约 (Safety)  │ 绝对无痕还原、零侵入、零破坏生命周期│
       ├─────────────────────────┼──────────────────────────────┤
       │ 4. 崩溃自愈守护(Sentinel)│ 崩溃即刻复原物理屏幕，软件设置全失效│
       ├─────────────────────────┼──────────────────────────────┤
       │ 5. 屏幕无感继承(Inherit)│ 首次启动取屏幕物理亮度，不分白夜即调即存│
       └─────────────────────────┴──────────────────────────────┘
```

### 1.1 物理真实的光学深度 (Dual-Track Dimming Model)
- **拒绝“平涂灰黑”**：传统调光工具在屏幕上方粗暴叠加半透明黑色矩形，导致画面呈现脏灰发闷质感，且底层物理背光依旧高压漏光刺眼。
- **无缝双轨光能模型**：
  - **10% ~ 100% 物理背光轨**：通过底层 DDC/CI I2C 硬件总线直接调节显示器物理背光，真实降低功耗（28.0W ➔ 4.2W）与光子辐射；
  - **0% ~ 10% 穿透微光轨**：硬件到达 10% 临界下限后，无感交接给纯黑透明遮罩，模拟物理中性灰滤光镜（ND Filter）的深邃水墨质感；
  - **100% 鼠标点击穿透**：全屏遮罩挂载 `WS_EX_TRANSPARENT | WS_EX_LAYERED | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` 扩展样式，日常点击操作穿透率 100%，绝对不阻挡游戏、视频或办公交互。

### 1.2 连续超椭圆与流体触感 (Continuous Squircle & Vibrancy)
- **数学级超椭圆曲率（\(n = 4\)）**：摒弃机械单圆弧切点，采用连续曲率超椭圆（Squircle 22px），配合 0.5px 极微半透晶体倒角高光折射（0.5px Specular Rim Light）。
- **纯净透明底板**：基于 `Qt.WA_TranslucentBackground`，背景四角四周 Alpha = 0 纯净透明，彻底杜绝 Windows DWM 粗暴注入带来的直角黑斑。

### 1.3 系统的神圣契约：非破坏性生命周期与崩溃自愈守护 (Crash Sentinel & Non-destructive Lifecycle)
- **启动物理快照与无损备份**：启动第一时间在内存中精准备份屏幕初始物理背光值与 GDI 16-bit Gamma Ramp 色温曲线；
- **全生命周期无痕还原**：退出软件、关机、休眠或使用紧急脱困热键（`Ctrl+Alt+Backspace`）时，**100% 逐字节精准恢复系统初始屏幕状态**，绝不修改注册表，绝不污染系统显示设置；
- **崩溃自愈与软件设置全部失效保障 (Crash Guardian Sentinel)**：
  - **如果软件崩溃了，必须恢复屏幕之前的亮度和色温，软件设置的全部失效**。
  - **双重自愈防护网**：
    1. **进程内全局异常急救拦截链**：通过 `sys.excepthook` 全局接管未捕获异常，在 Python 异常退出的最后一刻执行硬件背光复原与 Gamma Ramp 还原；
    2. **独立无界面崩溃守护子进程 (`src/crash_guard.py`)**：主进程启动时启动独立守护子进程，守护进程阻塞在 Windows 内核对象 `WaitForSingleObject` 上（0% CPU 占用）。若主程序遭遇 C 级崩溃、被任务管理器强杀或异常闪退（未生成 `clean_exit.flag`），守护进程在毫秒级感知，立即调用硬件接口**将屏幕物理亮度还原至启动前数值，并无损恢复原始 Gamma 色温，使得软件所做的全部调光设置立即失效**，彻底杜绝黑屏死锁或偏色遗留。

### 1.4 首次启动屏幕继承与即调即存体系 (Hardware Inheritance & Instant Persistence)
- **首次亮度默认按照屏幕物理亮度得来**：
  - 首次启动软件（无历史保存配置），**默认直接按照当前显示器屏幕原本的真实物理亮度启动，严禁手动硬编码（如固定 50%），且绝不区分白夜（不根据系统时间强制划分白昼与夜间，不强制设置预设）**；
- **即调即存（Instant Auto-Save）**：
  - 用户调整亮度的任何时刻（滑块拖拽、滚轮微调、快捷键步进、情境胶囊），程序立即持久化保存该亮度至配置文件；
- **下次启动记忆呈现**：
  - 下次启动软件时，自动读取并精确显示上次保存的用户设定亮度。

### 1.5 单实例互斥与窗口自然层叠 (Single Instance Sentinel & Stacking)
- **命名互斥体守护**：在 `src/main.py` 启动第一时间通过 Win32 `kernel32.CreateMutexW` 创建 `Global\\LunaDimmer_SingleInstance_Mutex_2026`。若已存在运行实例，即刻激活已有主窗口并毫秒级退出当前进程，确保全局永远仅有唯一实例常驻。
- **自然层叠不强占**：主面板绝不设置 `Qt.WindowStaysOnTopHint`，展示后自然融入 Windows 桌面工作流，允许被全屏视频或网页自然遮挡，不霸占视觉前景。

### 1.6 跨代级 Windows 全平台架构兼容体系 (Windows 7 / Windows 10 / Windows 11)
- **底层架构全兼容保障**：
  - **指针位宽自适应**：在 `src/win32_compat.py` 中，动态探测 32 位与 64 位指针位宽（4/8字节），智能桥接 `GetWindowLongPtrW` / `GetWindowLongW` 与 `SetWindowLongPtrW` / `SetWindowLongW`，杜绝 64 位系统指针截断或 32 位系统缺失 API 异常；
  - **Windows 7 深度适配**：
    1. **字体自动回退**：自动感知 Windows 7 环境并选用系统内置的 `"Microsoft YaHei"`（微软雅黑），避免因缺少 Win8+ 引入的 "Microsoft YaHei UI" 产生字体截断或排版漂移；
    2. **DDC/CI 优雅降级全域遮罩**：若 Windows 7 台式机显卡驱动未启用 DDC/CI 硬件通信，核心引擎自适应启动全域 1%~100% 穿透遮罩平滑接管，确保调光功能 100% 可用；
    3. **DWM Aero 合成容错**：窗口与遮罩使用经过验证的 Win32 `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` 规范样式，无论 Windows 7 开启 Aero 还是经典主题均能无感穿透；
  - **Windows 10 / 11 现代特性融合**：
    - 针对 Windows 10 与 11，启用原生高 DPI 缩放（`AA_EnableHighDpiScaling` 与 `AA_UseHighDpiPixmaps`）、独占任务栏 AppUserModelID、以及针对 Windows 11 居中托盘的智能边界吸附。

### 2.2 核心交互控件定义（直观易懂名称）
1. **动态亮度天体核心 (Living Luminary)**：
   - **高亮环境（≥70%）**：散发晨曦浅金色散射日冕（Golden Solar Corona）；
   - **柔和微光（20%~70%）**：演变为静谧银白的高光渐变弦月（Silver Crescent）；
   - **助眠极暗（<20%）**：月球进入 12 秒深空微光呼吸律动（Deep Starlight Pulse），带来睡前安神陪伴。
2. **macOS 控制中心厚胶囊滑块 (Capsule Slider)**：
   - 高度 42px，21px 圆角胶囊，内嵌液体水银白 / 琥珀流光填充条；
   - **双色域动态反色裁切（Dual-Contrast Inversion）**：滑块进度滑过左侧图标与右侧数值时，明暗边界像素级自适应反色，任何刻度均清晰锐利；
   - **全域线性调节与贴边归零**：支持 `0% ~ 100%` 连续拖拽，0% 处隐藏边缘高光线与阴影；
   - **鼠标滚轮悬停微调**：鼠标停留在滑块上滚动时，以 1% 步进精细递增/递减。
3. **常用场景预设 (Scene Presets) 与 深度压暗微芯片 (Deep Dimming)**：
   - 快速切入常用环境基准：`[ ☀️ 白天办公 90% ]`、`[ 🌙 夜间阅读 30% ]`、`[ 🛌 睡前极暗 5% ]`；
   - `[ ⚡ 深度压暗 ]`：激活硬件加速下潜（突破物理显示器最低亮度限制，遮罩提前深度介入）。
4. **一键黑屏挂机磁贴与全局鼠标晃动柔和点亮 (Blackout Screen & Bezier Wake)**：
   - 专为夜间听歌挂机、下载设计，点击一键进入 99.5% 极限黑屏（电脑不休眠、音频不中断）；
   - **三次贝塞尔缓动唤醒（1.5s OutCubic）**：拒绝粗暴爆闪，屏幕以电影级质感慢速柔和点亮；
   - **鼠标晃动感知与进场防抖**：进入黑屏前 350ms 忽略微动，350ms 后通过全局无侵入式光标轮询检测物理位移超过 20px 时即刻触发柔和唤醒。
5. **自绘微光窗口控制点 (Vector Window Control Dots)**：
   - 抛弃系统字库 Emoji/字符，采用 QPainter 硬件抗锯齿自绘纯几何矢量圆点；
   - 悬浮融入背景，中国习惯最右为关闭：🟢 设置 (`⚙`) ➔ 🟡 最小化至托盘 (`─`) ➔ 🔴 关闭退出 (`✕`)。
6. **任务栏与托盘停靠对齐 (Taskbar & Tray Docking)**：
   - 具备 Windows 任务栏专属图标与标准 Alt+Tab 切换轮廓；
   - 点击托盘图标智能呼出，自动吸附在当前光标所在显示器的右下角托盘正上方。

### 8.3 议题三：现场抓包发现的技术暗礁——DDC/CI I2C 慢速总线雪崩与磁盘 IO 磨损

- **Marcus (Apple 显示管线)**：“我们在评审中用硬件抓包工具分析了滑块拖拽行为，发现了一个隐藏的严重工程隐患：
  - 用户在快速拖动大滑块时，鼠标事件以 60Hz~120Hz 高频触发 `valueChanged`，旧代码在每一个像素移动时都在调用 `sbc.set_brightness()` 和 `config.save()`！
  - **DDC/CI I2C 物理总线速率只有 100kbps 甚至更低，单次包往返需要 20ms~50ms**！如果你在 1 秒内连续轰入 60 个 I2C 硬件包，显示器内部 MCU 会严重丢包甚至总线死锁，主线程被同步阻塞，导致界面掉帧卡死；同时每秒 60 次写入 SSD 也在浪费硬盘寿命！”
- **Zack (ByteDance 内核)**：“这个问题必须立刻根治。我们的重构方案是：
  1. **双轨分离节流 (40ms Sliding Window)**：滑块视觉动画与透明穿透遮罩继续以 60FPS 满帧实时渲染（内存计算，零延迟）；但对底层 DDC/CI 物理硬件通信加上 40ms 滑动窗口节流，拖拽过程中硬件按 25Hz 平滑更新，彻底消除总线堵塞；
  2. **拖拽释放终态同步 (`sliderReleased`)**：当用户松开鼠标按键的一瞬间，强制触发一次精确的终态硬件同步 (`force_hw=True`) 并持久化写入磁盘。既保证手感极其跟手，又保护了硬件安全。”

### 8.4 议题四：软件崩溃屏幕还原——这是决定产品生死存亡的“契约底线”

- **Kira (ByteDance 增长)**：“很多小工具为什么被用户怒删并打上一星差评？因为用户把屏幕调暗到了 5%，结果软件意外崩溃闪退，屏幕依旧卡在 5% 的黑漆漆状态，用户找不到恢复按钮，甚至以为自己屏幕坏了！**‘软件崩溃后，必须恢复之前的亮度和色温，软件设置全部失效’，这是生命线。**”
- **Zack (ByteDance 内核)**：“在 Windows 系统上，物理背光（VCP Feature 0x10）是直接写入显示器板载芯片的，操作系统内核绝不会在进程崩溃时帮我们还原它。因此，我们在架构上做到了两层绝对防线：
  1. **第一层（进程内急救链）**：`sys.excepthook` 接管所有 Python 未捕获异常，在退出前的最后一毫秒无损还原物理亮度和 Gamma；
  2. **第二层（进程外独立守护子进程 `src/crash_guard.py`）**：以无界面方式后台启动，阻塞在 Windows 内核对象 `WaitForSingleObject` 上（CPU 占用绝对为 0.00%）。不管是遭遇段错误、内存溢出闪退还是被任务管理器直接 End Process，守护进程在主进程句柄释放的 50ms 内即可捕获，强行调用硬件接口将物理背光和色彩恢复至启动前初始状态！所有软件设置即刻全失效，让用户完全无后顾之忧。”
- **Liam (Apple HI)**：“这种防御机制具有企业级工具的尊严。用户不用担心任何误操作或异常会导致电脑不可用。”

### 9.12 RFC-13: 大厂工程严审优化与全链路卡顿根治 (Big-Tech Audit, Non-Blocking Async DDC/CI & I/O Governance)
- **设计初衷与人机工程洞察**：
  依照一线大厂（Apple、Google、Microsoft）生产级桌面端与 Web 端的严苛工程标准，对全项目进行代码审计与性能优化，彻底消灭未达标的阻塞调用、冗余死代码、伪逻辑与布局抖动：
- **核心工程重构与优化项**：
  1. **异步硬件通信守护线程 (Non-Blocking DDC/CI Async Coalescing Worker)**：
     - **现状痛点**：DDC/CI I2C 慢速串行总线写入存在 50ms~150ms 的物理延迟，原先在 Qt GUI 主线程执行，当用户高频拖动或滚轮快速滚动滑块时，会造成严重的 GUI 主线程阻塞与画面掉帧；
     - **重构方案**：在 `BrightnessEngine` 引入专用后台守护线程 `LunaHwBrightnessWorker` 与聚合任务队列（Coalescing Queue，容量为 1），拖拽期间自动折叠中间过程帧，只在后台串行提交最新的背光写入指令，彻底解耦 UI 渲染与硬件通信；在软件退出 `restore_on_exit()` 时清空队列并执行同步无损还原，兼顾 120fps 丝滑操控与退出还原的 100% 确定性；
  2. **高频拖拽磁盘 I/O 节流与解耦 (Disk I/O Throttling & Drag Debouncing)**：
     - **现状痛点**：`main_window.py` 在 `set_brightness` 和 `set_warmth` 每次微小步长变化（`valueChanged` 每秒数十次）时均调用同步 `self.config.save()`，造成高频 JSON 磁盘写入风暴与磁盘抖动；
     - **重构方案**：移除了 `main_window.py` 每次值变化时的直接保存，统一收敛至 `BrightnessEngine` 内的 200ms 时间戳节流窗口；并在滑块释放信号（`sliderReleased`）处绑定即时落盘，大幅降低无谓的磁盘开销；
  3. **网络与更新服务防伪延迟清理 (Network Mock Latency Cleanup)**：
     - **现状痛点**：`src/services/updater.py` 在检测版本更新时，无论是否为真实网络请求，无条件休眠 `time.sleep(1.2)`；
     - **重构方案**：将强制延迟限制在调试模式（`force_simulate_update is True`）分支，真实 GitHub Release API 请求取消人为阻塞，网络请求返回即呈现；
  4. **Web 演示端死代码清理与真实热键录制器 (Web Dead Code Stripping & Native Key Recorder)**：
     - **清理死代码**：剥离 `web/js/simulator.js` 中被 `presets.js` 覆盖的同名阴影函数 `applyPreset` 以及无调用的废弃测试辅助函数（`handleSliderClick`, `handleWarmthClick`, `demoDualTrack`, `demoLivingOrb`, `demoKeyboardStep`, `copyCliCommand`）；
     - **真实热键录制**：将 `web/js/modals.js` 中假借 1 秒 `setTimeout` 的虚假热键录制重构为真实 `keydown` 原生事件捕获器，支持 `Ctrl`/`Alt` 修饰键校验、冲突检测与实时持久化；
     - **Canvas 光学曲线去抖**：移除 `drawLiveGammaRamp` 中昂贵的 `ctx.shadowBlur = 6`，改用轻量双通发光绘制，消除 Gamma 曲线重绘时的 GPU 开销；
     - **盲操快捷键双向打通**：在网页端补齐快捷键监听（`Ctrl+Alt+Up/Down/S/B/F/Backspace`），使网页仿真与桌面端体验 1:1 对齐；
     - **文案与表格补全**：修复 `index.html` 快捷键表格文案笔误（“一键一键黑屏挂机” ➔ “一键黑屏挂机”），并补充 `Ctrl+Alt+F`（暗夜微光聚光灯透视）说明行；
  5. **分层门面架构完整性加固 (Layered Architecture Facades Integrity)**：
     - 在 `src/ui/widgets/` 目录下补齐 `capsule_slider.py`、`living_luminary.py`、`toggle_chip.py`、`preset_dialog.py` 四个对齐门面模块，使整洁分层架构中 `src.widgets.*` 与 `src.ui.widgets.*` 双向完全无缝兼容。

## 10. 大厂整洁分层架构与防代码臃肿工程规范 (Clean Layered Architecture & Anti-Bloat Engineering Governance)

### 10.1 架构演进背景与设计哲学
早期项目中，随着功能快速迭代，settings_dialog.py 膨胀接近 2000 行，包含通用设置、光学微调、快捷键注册、崩溃自愈、恢复默认与视觉样式渲染，成为典型的「上帝对象（God Object）」。任何微小的需求变更，都需要开发者将全量代码重读一遍，存在极高的上下文认知负荷与回归风险。

   - **容器架构**：SettingsDialog 仅负责创建左侧导航、三段式主题分段器和底部操作栏，子页面各自独立管理其控件、数据同步与槽函数。

## 11. 独立可执行程序构建系统与跨平台字符集防御标准 (RFC-15)

### 11.1 Windows CMD 字符集错位与乱码成因剖析
Windows 环境下的 `cmd.exe`（Command Prompt）与 PowerShell 终端在中文操作系统中默认采用代码页 **CP936 (GBK)**。
当构建批处理文件 `build_exe.bat` 或 Python 构建脚本 `scripts/builder.py` 运行时，极易因以下原因产生视觉乱码：
1. **换行符断裂 (LF vs CRLF)**：Windows `cmd.exe` 解析器原生基于 CRLF (`\r\n`) 维护文件偏移量指针。若批处理脚本误保存为 Unix LF (`\n`)，复合逻辑块 `(...)` 与 `goto` 跳转将发生字节偏移错位，导致命令被截断并倾泻未转义字符；
2. **控制台窗口标题 (Console Title)**：`chcp 65001` 生效后，`cmd.exe` 内部的 `title` 命令依旧调用底层 ANSI 接口，若传入多字节 UTF-8 中文字符串，窗口标题栏将呈现 `鏈堝厜灞忓箷璋冨厜鍣` 等典型乱码；
3. **ANSI 转义序列泄露**：在未开启 VT100 / Virtual Terminal 模式或无第三方库的经典 ConHost 窗口中，24-bit TrueColor 转义代码（如 `\033[38;2;...m`）无法被解析，直接泄漏为 `←[38;2;245;179;56m` 等生硬控制符；
4. **Emoji 与字体缺字 (Glyph Missing)**：经典宋体 (SimSun) 终端点阵字体不含 4 字节 UTF-8 Emoji（如 `🌙`）及非常规几何符号（如 `◓ ◑ ◒ ◐`），会导致制表符断裂或字符显示为问号方块。

### 11.2 RFC-15 工业级跨终端防御工程规范
为确保无论用户在何种 Windows 版本（Windows 7/8/10/11）、何种终端环境（CMD、PowerShell、Windows Terminal、VSCode）及何种默认代码页下点击 `build_exe.bat` 均能获得完美的视觉呈现与零乱码体验，确立以下防御标准：

1. **批处理文件强制 CRLF 与动态代码页绑定**：
   - `build_exe.bat` 必须且只能采用 **UTF-8 无 BOM + Windows CRLF (`\r\n`)** 保存；
   - 脚本头部统一声明 `@chcp 65001 >nul 2>&1`，并设置 `PYTHONIOENCODING=utf-8` 与 `PYTHONUTF8=1`；
   - 窗口标题统一采用纯 ASCII 英文（`title Luna Dimmer - Build System`），防御系统标题栏乱码；
   - 错误提示采用中英双语，保证极端异常下亦可清晰定位。
2. **动态代码页侦测与标准流自适应 (`setup_io_encoding`)**：
   - 通过 Win32 API `kernel32.GetConsoleOutputCP()` 动态侦测当前控制台真实代码页；
   - 代码页为 65001 时定向重设为 `utf-8`，代码页为 936 时定向重设为 `gbk`，均附带 `errors="replace"` 柔性防御。
3. **ANSI 配色引擎双轨降级机制 (`Colors`)**：
   - 优先通过 `colorama.init(autoreset=False)` 激活 Win32 控制台属性转换；
   - 备用方案通过 64 位 Win32 API 精准开启 `ENABLE_VIRTUAL_TERMINAL_PROCESSING (0x0004)`；
   - 严禁启用 `DISABLE_NEWLINE_AUTO_RETURN (0x0008)` 避免梯形错位；
   - 若终端完全不支持 ANSI，全量配色代码平滑降级为 `""` 空字符串，杜绝任何原始转义码泄露。
4. **全字符集通用视觉符号标准**：
   - 边框采用 GBK 与 UTF-8 共有双字节标准制表符：`┌ ┐ └ ┘ ─ │`；
   - 进度条采用通用双轨符号：`■`（填充）与 `□`（空槽）；
   - 状态标识采用通用符号：`√`（成功）与 `×`（失败）；
   - 旋转指针采用无缺字字符：`["[-]", "[\\]", "[|]", "[/]"]`；
   - 移除 4 字节 Emoji，以 `[Luna]` 等精巧文本代币替代，保证表格与看板像素级对齐。

### 12.1 剔除杂质与三大主题物理材质重定义
Luna Dimmer 作为 macOS 控制中心设计哲学的最高标准落地，彻底剔除 Tailwind 默认预设冷泥色阶、Web3 赛博朋克霓虹光晕及复古 3D 杂质元素，重塑纯粹的苹果工业级材质空间：

1. **☀️ 浅色主题 (Snow White Porcelain)**：
   - **底板材质**：雪山瓷白高光毛玻璃（`rgba(255, 255, 255, 0.98)` 到 `rgba(242, 242, 246, 0.98)`），辅以 0.5px 天顶反光微光；
   - **文字与层级**：主文本采用 Apple 极简纯炭黑 `#1D1D1F`（88% 灰阶），副文本采用 `rgba(60, 60, 67, 0.70)`，彻底消灭 Slate 蓝泥浊色；

   - **流体纯白填充**：滑块填充柱统一采用纯净实心水银白（`#FFFFFF`）与温润日光琥珀（`#FF9F0A`），彻底剥离廉价的赛博青蓝荧光外发光。

   - **光学中性与白晶微切**：全量文字与标识回归纯白与半透白，边框采用顶部 0.5px Specular 全反射切角；彻底清除人造的 Tron 青蓝涂装（`#38BDF8`）与内部彩虹混杂漏光。

### 12.7 偏好设置交互卡死自愈体系与全场景双通道运行日志系统 (RFC-20)

1. **全局事件过滤器竞态隔离 (EventFilter Race Isolation)**：

3. **设置窗口全生命周期交互状态强保活与外部链接解耦 (Dialog Lifecycle & External Link Decoupling)**：

   - 彻底解决单文件打包（`LunaDimmer.exe` 配置 `console=False`）无控制台输出导致无法排查故障的盲区；
   - 在 `src/main.py` 启动阶段自动初始化 `logging.handlers.RotatingFileHandler`，将运行时诊断日志落盘至 `%APPDATA%\LunaDimmer\logs\luna_runtime.log`（单文件 3MB，3 份历史滚动备份）；

### 12.8 人机安全可视底限与防死黑脱困体系 (RFC-21)

针对用户在将屏幕亮度拖曳至极低区间（0%~1%）时，屏幕因遮罩不透明度过高（原 0.92~0.96）导致完全漆黑一片、无法看清界面任何按钮、产生严重人机困境（用户完全不知道点哪里）的问题，确立人机安全底限与立体脱困体系：

1. **人机安全可视微光底限 (Safe Visual Floor)**：
   - **日常滑块调光物理封顶**：在 `compute_levels` 算法层将日常滑块调光的遮罩不透明度严格锁死在人机安全底限：
     - 标准模式下 `ov <= 0.80`（保留 20% 环境穿透光）；
     - 2x 深度压暗模式下 `ov <= 0.82`（保留 18% 环境穿透光）；
     - 无物理硬件支持兜底模式下 `ov <= 0.80`；
   - **视网膜微光可读性**：18%~20% 的微光底限确保在全黑暗室中，高对比度文字、UI 图标与鼠标光标依然清晰可辨，彻底杜绝误将整个屏幕拖进漆黑死境的心理恐慌。

2. **纯黑挂机与日常调光严格物理隔离 (Stealth Separation)**：
   - 极限纯黑遮罩（`0.995` 接近 OLED 纯黑）严格收敛于专用的「`[ 🎧 一键纯黑挂机 (黑屏听歌/下载) ]`」功能；
   - 纯黑挂机具备完备的即时唤醒保障：内置 350ms 防抖 + 20px 鼠标晃动即刻平滑苏醒、键盘任意按键苏醒以及点击苏醒，绝不产生交互死局。

3. **极暗荧光轮廓指引 (Phosphor Visual Affordance)**：
   - 当亮度滑块处于 `<= 10%`（或 2x 深度压暗下 `<= 15%`）极暗区间时，主面板右上角「`↺ 恢复原状`」按钮（PyQt `btn_reset` / Web 端 `btnMockReset`）自动激活金琥珀荧光高亮轮廓（`border: 1.5px solid #F5B338`, `background: rgba(245, 179, 56, 0.22)`, `color: #FBBF24`）与立体光晕；
   - 鼠标悬浮提示与状态栏即刻同步提示应急脱困文案：`太暗看不清？点击这里立即恢复系统原状 (或按 Ctrl+Alt+Backspace 紧急唤醒)`。

4. **多通道全方位紧急脱困体系 (Multi-tier Emergency Escape)**：
   - **物理鼠标脱困**：荧光高亮「`↺ 恢复原状`」微晶胶囊，一键毫秒级直达 100% 满光与中性色彩；
   - **键盘盲按脱困**：主界面处于极暗区间时，单按 `Esc` 键直接等同于紧急脱困（触发 `reset_to_system_default` 恢复满光），无需寻找界面控件；
   - **全局系统级热键脱困**：无论处于前台、后台还是黑屏，全局热键 `Ctrl+Alt+Backspace` 始终常驻，瞬时强制清除所有遮罩并复位背光。

### 12.12 零服务器极客架构：版本更新判定与无后台反馈闭环体系 (RFC-25)

针对独立桌面软件在“无专属云服务器、无独立后端数据库”场景下的运维诉求，确立成熟的 Serverless 零服务器极客运维架构：

1. **版本更新判定：纯静态 `version.json` + Cloudflare Pages 全球 CDN 分发**：
   - **更新判断本质**：客户端无需动态接口，仅需通过标准 HTTP GET 请求读取网络上的纯静态 JSON 元数据（`version.json`）；
   - **多通道零成本高可靠轮询 (`src/services/updater.py`)**：
     - **主通道**：托管在 Cloudflare Pages 静态网站根目录（`https://lunadimmer.pages.dev/version.json` 或自定义域名），享受 Anycast 毫秒级边缘缓存；
     - **备用通道 1**：GitHub Releases / Raw 镜像（`https://raw.githubusercontent.com/.../version.json`）；
     - **备用通道 2**：jsDelivr 全球开源 CDN 镜像（国内免代理极速访问）；
   - **SemVer 语义化三段式比对**：云端版本严格大于客户端 `CURRENT_VERSION` 时，触发 `UpgradeDialog` 弹窗并展示对应语言的更新日志与安装包下载链接。
2. **问题反馈收集：Cloudflare Worker 无服务器函数 / 免费 Webhook 手机直达**：
   - **架构解耦**：客户端 `FeedbackDialog` 在保留本地时间蜜罐、频控防洪与算术防刷的基础上，集成异步 `FeedbackSubmitWorker`；
   - **手机秒收通知闭环**：
     - 借助 Cloudflare 免费 Worker（每日 100,000 次免费请求额度），将用户 POST 的反馈数据即刻转发至微信推送平台（如 PushPlus / Server酱）或飞书/企业微信机器人；
     - 用户在客户端提交反馈，开发者手机微信或移动办公端在 1 秒内收到卡片提醒，完全免去自建云主机、免去部署 MySQL/Nginx 的繁重成本；
   - **优雅离线降级与透明归档**：
     - 本地脱机状态或未配置云端 Webhook 时，自动保存至 `feedback_logs/`，同时一键将反馈文本与脱敏系统快照复制至剪贴板，方便用户直接通过 GitHub Issues 或邮件与开发者交流。

## 13. 工程健壮性加固与一致性修复总纲 (RFC-29)

本节记录一轮以「可靠性、线程安全与单一真相源」为目标的系统性加固。所有条目均已在代码中落地，后续维护须遵循同样的边界。

### 13.1 生命周期与线程安全

1. **全局热键回调的跨线程投递（关键修复）**：
   - 旧实现直接在 Win32 热键消息泵线程里调用 `QTimer.singleShot(0, ...)`。该线程没有 Qt 事件循环，定时器不会触发；即便触发也是跨线程操作 QWidget。
   - 现统一由 `src/ui/main_window.py` 中的 `GuiDispatcher`（QObject + `pyqtSignal(object)` + 显式 `Qt.QueuedConnection`）把回调排队回 GUI 线程。
   - **动作 → 回调映射表只有一份**：`LunaMainWindow._hotkey_callbacks()`。`src/main.py` 不再维护第二份表，新增热键只需改这一处。
2. **退出还原竞态**：`BrightnessEngine.restore_on_exit()` 现在按「停用引擎 → 取消尾部 Gamma 定时器 → 清空队列 → join 硬件线程 → 同步还原」的顺序执行，杜绝后台线程在还原之后又把暗值写回硬件。
3. **色温写入节流**：Gamma 写入做 40ms 节流，并用一次性守护定时器做尾部兜底补写，保证拖动顺滑且最终值必达。

### 13.2 数据与系统调用

1. **配置原子持久化**：`ConfigManager.save()` 走 `tmp → fsync → 滚动 .bak → os.replace`，且永不抛异常；`load()` 在主文件损坏时自动从 `.bak` 恢复并重建主文件。
2. **64 位句柄安全**：`crash_guard` 与单实例互斥锁的所有 Win32 调用均显式声明 `argtypes/restype`；`WaitForSingleObject` 返回值被严格判定，`WAIT_FAILED` 时退化为低频轮询，绝不在主进程存活时误还原。
3. **崩溃守护轻量启动**：`--crash-guard` 分支被提前到任何 PyQt `import` 之前；`src/__init__.py` 改为 PEP 562 惰性导出，`import src.*` 不再连带拉起整个 UI 栈。
4. **开机自启命令行**：源码运行注册 `"<pythonw.exe>" "<绝对路径>/src/main.py" --silent`（注册表 Run 项的 cwd 是 System32，不能依赖 `-m`）；冻结模式注册 exe 本体。
5. **多显示器 Gamma**：通过 `EnumDisplayDevicesW` 为每台显示器建 DC，色温对所有屏幕生效，备份/还原按设备名逐个进行（备份文件升级为 v2 映射格式，同时兼容旧的纯数组格式）。
6. **热键冲突检测**：`test_hotkey_availability` 改用独立 `use_last_error=True` 的 user32 句柄读取 1409 错误码，并接受 `current_key` 以消除「自己占用自己」的误判。

### 13.3 单一真相源与文档一致性

1. **版本号**：唯一来源是 `src/services/updater.py::CURRENT_VERSION`；托盘提示、反馈 UA/诊断快照均从它派生，`version.json` 必须与之同步。
2. **图标**：`src/styles/app_icon.py` 是托盘与任务栏图标的唯一绘制实现。
3. **spec**：`LunaDimmer.spec` 是打包配置的唯一来源，`scripts/builder.py` 不再内嵌整份副本（缺失即报错）。
4. **控件层方向**：真实实现在 `src/widgets/`，`src/ui/widgets/` 为兼容门面（见 10.4 的方向约定）。

### 13.4 已知偏差与后续整改（诚实记录）

1. `src/ui/main_window.py` 仍超过 2000 行（含 3 个自绘控件与全量主题样式），与 10.6 的 300/500 行戒律冲突。后续应按「自绘控件 → `src/widgets/`、主题样式 → `src/styles/theme_styles.py`」继续外迁。
2. `src/ui/dialogs/preset_dialog.py`、`sponsor_dialog.py`、`feedback_dialog.py` 仍偏大，可在不改交互的前提下继续抽离视觉片段。
3. 各弹窗仍有较多内联样式字符串，尚未全部收敛到 `ThemeTokens`；新增样式必须直接使用代币，禁止继续新增硬编码色值。

### 13.5 应用内全自动静默覆盖与热重启引擎 (In-App Auto-Update & Process Hot-Replacement)

针对 Windows 系统下正在运行的可执行程序文件句柄被内核死锁、无法直接覆写的痛点，构建 100% 可靠的脱离伴生重启链路：
1. **脱钩伴生批处理脚本 (Detached Companion Process)**：
   - 生成独立的脱钩批处理脚本（`CREATE_NO_WINDOW | DETACHED_PROCESS`）；
   - **绝对规避 `timeout` 崩溃陷阱**：在后台无控制台/输入重定向环境中，Windows `timeout` 会直接报错 `错误: 不支持输入重定向，将立即退出该进程` 并中断脚本。必须全量使用无害的 `ping 127.0.0.1 -n 2 >nul` 实现毫秒级延时；
   - **目录锁定与原子替换**：在脚本首行显式执行 `cd /d "{exe_dir}"` 切换至程序目录，通过 `move /y` 原地覆盖；若遇文件锁延迟，通过 Windows NTFS 允许重命名的特性回退执行 `ren` 重命名覆盖，并自动清理历史残留；
2. **内核层进程强制瞬时释放 (`os._exit(0)`)**：
   - 杜绝在 Qt 定时器或槽函数中仅调用 `sys.exit(0)`（会被 PyQt 内部 C++ 异常捕获机制截留导致进程无法退出）；
   - 伴生脚本唤起后，立即调用 `os._exit(0)` 在 C 运行时内核层强制终结当前旧主进程，瞬时释放可执行文件的全部系统句柄，确保伴生脚本毫秒级拉起全新版本。
